# Finding codes: build, release and verify

> Offline copy. Read the official docs for your version at https://olejbondahl.github.io/fransys/X.Y.Z/ (X.Y.Z is `fransys.__version__`), or https://olejbondahl.github.io/fransys/X.Y.Z/llms.txt. Use this copy only offline.

Codes the build, `release`, `verify` and the baseline check emit. Who acts is explained in [`findings.md`](findings.md).

| Code | Severity | Stage | Who acts | Meaning | Fix |
| --- | --- | --- | --- | --- | --- |
| BASELINE_DIFFERS | ERROR | release, verify | consumer | A unit instance in the released subtree, or checked by `verify`, has a listing differing from its released baseline. | Bump the changed unit's revision and release it again, or restore its content. Write: fr.release(result, into, unit=<unit>) |
| BASELINE_ROWS_UNCHECKED | INFO or ERROR | release, verify | consumer | A stored baseline cut before fransys 0.18.2 holds rows for a contact block that today's numbering cannot print. Every other row is unchanged, and those rows were left out of the comparison. `verify` notes it (INFO); `release` of a unit nesting it refuses (ERROR). | Re-cut the stored baseline, which records its rows under today's rules. Write: fr.rebaseline(result, baselines, unit=<unit>) |
| BASELINE_RULES_MOVED | INFO or ERROR | release, verify | consumer | A stored baseline's content is unchanged, but a later fransys prints its listing differently. `verify` notes it (INFO); `release` of a unit nesting it refuses (ERROR). | Re-cut the stored baseline under today's rules first. Write: fr.rebaseline(result, baselines, unit=<unit>) |
| BASELINE_TOO_OLD | ERROR | release, verify | consumer | A stored baseline was cut by a fransys older than the oldest release whose listing rules this build knows, or its manifest records no fransys version. | Verify with the fransys release that cut the baseline, or release a new revision. Write: fr.release(result, into, unit=<unit>) |
| CHANGES_BY_NAME | INFO | build | note | The release the next change list starts from was cut before listing version 2, so it names no item key. The change list matches by printed designation, and a renamed item shows as one removed and one added row. | The next release's change list follows renames; `fr.rebaseline` re-cuts the old release now. |
| EXPORT_NAME_CLASH | ERROR | build | consumer | Two different subjects (documents, items) would write to the same file name in `out_dir`. | Give <subject> or <other> a distinct name, location or fragment; a placement of a release is named by what `d.add` returned, which adds its tag to the PDF name. Write: fr.unit(<distinct name>, revision=<n>, interface_version=<n>, date=<date>, text=<text>, by=<by>) |
| INTERFACE_NOT_BUMPED | ERROR | release | consumer | The previous released revision of this unit (the highest below this one) has the same interface string but a different boundary. | Bump the interface version of <subject> if its boundary changed, or restore the previous boundary. Write: fr.unit(<name>, interface_version=<new>, ...) |
| RELEASE_FILE_CHANGED | ERROR | verify | consumer | A released file's hash differs, the folder holds a file its manifest omits, or the manifest does not parse. A CRLF-only change in a text file passes. | No call clears this: restore the file from version control; a released revision never changes. |
| RELEASE_FILE_MISSING | ERROR | verify | consumer | A file its manifest lists, or the manifest itself, is gone from a release folder. | No call clears this: restore it from version control. |
| RELEASE_HISTORY_UNRELEASED | ERROR | release | consumer | A history entry after the first released one names a revision with no folder under `into`, in its own version. | Remove the entry from history=, or release that revision first. Write: fr.release(result, into, unit=<unit>) |
| RELEASE_NESTED_UNRELEASED | ERROR | release | consumer | A unit anywhere in the subtree being released (not only direct children) has no baseline folder yet. | Release <subject> first, then release the containing unit. Write: fr.release(result, into, unit=<nested unit>) |
| RELEASE_NO_HISTORY | ERROR | release | consumer | The revision being released has no matching `Revision` history entry. | Add the missing entry: history= on fr.unit, or d.revision(...) for a system release. Write: fr.unit(<name>, ..., history=[<revision entry>]) |
| REVISION_ALREADY_RELEASED | ERROR | release | consumer | The unit (or system) being released already has a baseline folder whose listing differs from the one to be written. | Bump the revision or version, or restore the frozen revision's content. Write: fr.unit(<name>, revision=<new revision>, ...) |
| SETTING_NEW_ENGINE_ONLY | WARNING | build | consumer | A settings file sets a `[grid]` or `[font]` key. It applies to drawings from the new engine; the old engine, which draws every schematic today, keeps the built-in grid and font until MODEL-TEXT, so this finding goes then. | Keep the key for the new engine's drawings, or remove it from the settings file. Write: fr.settings() |
